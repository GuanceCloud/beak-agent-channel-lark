# 飞书工具审批卡片

工具审批使用 CardKit JSON 2.0 布局，由 `internal/lark/tool_approval_card.go` 动态生成，不依赖飞书后台的云模板 ID。Beak 通过可选 `tool_approval` 字段传入持久化请求的工具名、风险等级、已脱敏参数预览和截断标记；SDK 不解析 `summary` 获取业务状态，也不执行参数。

待确认采用橙色标题和批准本次操作/拒绝按钮；已批准绿色、已拒绝红色、已取消和已过期灰色。终态由宿主传入原 `message_id`，PATCH 更新原卡片并移除按钮。批准只代表授权通过，执行结果另行回复。宿主 Agent 仅在同一会话、同一发起人内复用相同工具和参数或显式审批范围的授权，不同群成员不共享批准；卡片明确提示该行为，不承诺仅执行一次，也不会修改完全访问权限设置。请求 ID、revision、操作 ID 和回调身份鉴权沿用原契约。

任意工具只要由 Beak 生成标准工具审批请求，即复用此布局，包含 bash/exec、文件操作及 MCP 工具。参数最多预览 1200 字符，超出时明确提示截断；工具名转义 Markdown，参数中的反引号和 HTML 定界符转换成 JSON Unicode 转义，避免改变布局。SDK 不负责识别或脱敏秘密，宿主只能传入已脱敏内容。

旧宿主未传入 `tool_approval` 时保持原摘要卡片；计划确认和补充输入沿用各自契约。本次不扩大 SDK 的原生输入能力，不修改应用权限。

验证：模块 `go test ./...` 包含 HTTP 边界的多工具、长参数、特殊字符、状态更新、按钮令牌回归；跨平台 conformance 另行执行。真实飞书展示与回调须由接入宿主在 Testing 验收。
